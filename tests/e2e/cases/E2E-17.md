# E2E-17 — Command parsing and idempotence

| | |
|---|---|
| **Group** | parsing |
| **Applies to** | every pass |
| **Scoped config** | none |
| **Run** | with the rest |

## The issue

**Title**

```
[E2E-17] Add a trailing-whitespace stripper
```

**Body**

```
Add `strip_trailing(s)` to `src/toolbox.py` removing trailing whitespace from each line of a
string, with one test.
```

## The process

| # | openclaw posts | wait for | then check |
|---|---|---|---|
| 1 | ``Reminder: post `/fix` when you are ready.`` — the command is mid-line | **no label at all** across two wake-ups | an embedded command must not dispatch. A command has to start a line |
| 2 | `/plan` newline `/fix` — one comment, two lines | `autoswe:fixed` | last one wins inside a single comment: the fix ran and the plan did not — no `autoswe:planning` was ever seen |
| 3 | *(post nothing — let three wake-ups pass)* | **no label change** | the command that already ran must not re-fire on every poll |
| 4 | `/fix` — textually identical to step 2's second line | `autoswe:fixed` again | a **second** fix ran: a new comment legitimately re-dispatches, and identical text is not deduplication |

## Status path

```
(nothing) → pending → fixing → fixed → (quiet) → pending → fixing → fixed
```

## Must never appear

`planning` · `planned` · `failed` · `error`

## Why this case exists

Four parsing rules, each one a plausible bug on its own:

- A command **must start a line**, or every issue that discusses `/fix` in prose would
  dispatch one.
- Inside one comment, the **last** command wins rather than all of them running.
- A command that has already been dispatched **must not re-fire** on the next poll. Getting
  this wrong is the classic infinite loop.
- The dedupe is by **comment identity**, not by text. Re-posting the same command is a new
  instruction and must run again.

Steps 3 and 4 are the pair that matters: too much dedupe and the user cannot repeat a command,
too little and the poller loops forever.
