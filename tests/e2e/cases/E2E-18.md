# E2E-18 — A command in the issue body, and closing the issue

| | |
|---|---|
| **Group** | parsing |
| **Applies to** | every pass |
| **Scoped config** | `auto_dispatch_new: true` on the test project — restore to `false` afterwards |
| **Run** | **alone.** While it is set, every new issue in the project dispatches on sight. |

## The issue

**Title**

```
[E2E-18] Add a version constant
```

**Body** — the first line is the command:

```
/plan

Add a `__version__ = "0.1.0"` constant at the top of `src/toolbox.py`.
```

## The process

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | *(nothing — the body carries the command)* | `autoswe:planned` | the task dispatched with **no comment posted at all**; a plan was produced |
| 2 | posts `/fix` | `autoswe:fixed` | the constant is on the task branch |
| 3 | **closes** the issue through the provider API | the label stays `autoswe:fixed` | closing is not an error and not a new state; the task is not re-run |
| 4 | **reopens** the issue | the label is still `autoswe:fixed` | the task was never purged — its history and branch survive the round trip |

## Status path

```
(new, body command) → pending → planning → planned → pending → fixing → fixed
                    → (closed) fixed → (reopened) fixed
```

## Must never appear

`failed` · `error`

## Why this case exists

Two independent things, both about autoSWE noticing state it did not create:

- A command in the **issue body** is as good as one in a comment, and with
  `auto_dispatch_new` on it dispatches without anyone commenting. Step 1 asserts the
  comment count stays at zero.
- **Closing an issue out from under a task** must be absorbed, not treated as a failure —
  and reopening must find the task exactly as it was. A task that is purged on close loses
  its branch and its history.

## Restore afterwards

Set `auto_dispatch_new` back to `false` before seeding any further cases, or every issue you
create next will dispatch itself.
