# E2E-16 — `/pr` blocked by a pending CI check

| | |
|---|---|
| **Group** | gates |
| **Applies to** | every pass |
| **Scoped config** | `PR_REQUIRE_CI` on (the default) — needs the CI lever from [`../SETUP.md`](../SETUP.md) |
| **Run** | with the rest, but this one is **timing-sensitive** |

## The issue

**Title**

```
[E2E-16] Add a ci_slow/marker.txt file
```

**Body**

```
Create `ci_slow/marker.txt` containing the word `marker`. Nothing else.
```

That path is what triggers the slow CI job, and nothing else in the suite touches it.

## The process

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | posts `/fix` | `autoswe:fixed` | the push started the slow job — the branch head has a check in progress |
| 2 | polls the commit status on the branch head | it reads **pending** | do not proceed until it does |
| 3 | posts `/pr` **while it is still pending** | `autoswe:failed` | the comment names the CI gate as the reason; **no PR was opened** |
| 4 | polls the commit status again | it reads **success** | the slow job finished |
| 5 | posts `/retry` | `autoswe:shipped` | the PR opened once CI was green |

Step 3 is the whole case, and it depends on posting inside a window a few minutes wide. Poll
the status API and post on the observation — never on a fixed delay.

## Status path

```
pending → fixing → fixed → pending → shipping → failed → pending → shipping → shipped
```

## Must never appear

`error`

## Why this case exists

Shipping is gated on CI being green, and the gate must be checked **before** a PR is opened,
not after. A PR created against a red or unfinished build is exactly what the gate exists to
prevent, so "no PR was opened" in step 3 is the assertion — the `failed` label alone does not
prove it.

Step 5 proves the failure is not sticky: once CI goes green, a plain `/retry` ships.
