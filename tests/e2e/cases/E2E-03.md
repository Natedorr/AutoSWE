# E2E-03 — `waiting` resumed by a slash command instead of a reply

| | |
|---|---|
| **Group** | questions |
| **Applies to** | every pass |
| **Scoped config** | none |
| **Run** | with the rest |

## The issue

**Title**

```
[E2E-03] Add a farewell helper - wording undecided
```

**Body**

```
Add `farewell(name)` to `src/toolbox.py`. I have not decided on the wording - ask me before
you write the plan. Do not guess.
```

## The process

| # | openclaw posts | wait for | then check |
|---|---|---|---|
| 1 | `/plan` | `autoswe:waiting` | a question comment was posted |
| 2 | `/fix with use "Bye, <name>"` | `autoswe:fixed` | the command won over plain reply-resume — the task went to the fix phase, **not** back to planning; `farewell()` returns `"Bye, ..."` |

## Status path

```
pending → planning → waiting → pending → fixing → fixed
```

## Must never appear

`planned` · `failed` · `error`

## Why this case exists

[E2E-02](E2E-02.md) proves a plain reply resumes the interrupted phase. This one proves the
opposite branch: when the reply **is** a slash command, the command wins — the task does not
resume planning, it starts the phase the command names, carrying the guidance with it.

`planned` in the must-never list is the real assertion. If it appears, the reply was treated
as an answer to the question rather than as a new command.
