# E2E-15 — `--branch`: work from a non-default branch

| | |
|---|---|
| **Group** | steering |
| **Applies to** | every pass |
| **Scoped config** | none — needs the second branch from [`../SETUP.md`](../SETUP.md) |
| **Run** | with the rest |

Substitute your second branch's name for `develop` throughout if it is called something else.

## The issue

**Title**

```
[E2E-15] Add a CHANGELOG stub on develop
```

**Body**

```
Add a `CHANGELOG.md` with a single `## Unreleased` heading. Nothing else.
```

## The process

| # | openclaw posts | wait for | then check |
|---|---|---|---|
| 1 | `/plan --branch develop` | `autoswe:planned` | the plan phase ran against `develop` |
| 2 | `/fix` | `autoswe:fixed` | the task branch was cut from **`develop`**, not the default branch — its history contains `develop`'s commits |
| 3 | `/pr` | `autoswe:shipped` | the PR's base is the repo's configured `base_branch` — **not** `develop` |
| 4 | `/fix --branch main` | `autoswe:fixed` | the second `--branch` was **ignored**; the task branch is still based on `develop` |

## Status path

```
pending → planning → planned → pending → fixing → fixed → pending → shipping → shipped
        → pending → fixing → fixed
```

## Must never appear

`failed` · `error`

## Why this case exists

Three rules about where work happens, none of them obvious:

- `--branch` on the first command chooses the branch the task is cut from.
- The **PR base is the configured base branch anyway** — the working branch and the merge
  target are different decisions. Step 3 pins this down; if it has since changed by design,
  this assertion is what tells you.
- `--branch` is set **once**. A later `--branch` on the same task is ignored rather than
  silently re-basing work in flight, which would abandon the commits already made.
