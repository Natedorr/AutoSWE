# E2E-06 — `/sync` with a clean merge

| | |
|---|---|
| **Group** | sync |
| **Applies to** | every pass |
| **Scoped config** | none |
| **Run** | with the rest |

## The issue

**Title**

```
[E2E-06] Append a line to docs/notes.md
```

**Body**

```
Append the line `e2e-06 touched this` to the end of `docs/notes.md`. Nothing else.
```

## The process

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | posts `/fix` | `autoswe:fixed` | the task branch exists with the appended line |
| 2 | commits a **new** file `docs/other.md` on the base branch, through the provider API, as an ordinary committer | — | the base branch has moved, and touches no file the task branch touched |
| 3 | posts `/sync` | `autoswe:synced` | a merge commit landed on the task branch, bringing `docs/other.md` with it |

## Status path

```
pending → fixing → fixed → pending → syncing → synced
```

## Must never appear

`failed` · `error`

## Why this case exists

The ordinary case for `/sync`: the base branch moved underneath a task branch, the two do not
overlap, and the merge is mechanical. No agent should be invoked at all — a clean merge is
plumbing, and paying a model to do it would show up here as an unexpected delay and an agent
comment on the issue.
