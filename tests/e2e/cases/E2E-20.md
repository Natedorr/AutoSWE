# E2E-20 — `/catchup` on a control issue, clean merge, then a repeat

| | |
|---|---|
| **Group** | catchup |
| **Applies to** | every pass |
| **Scoped config** | none |
| **Run** | with the rest |

## Setup (before the issue is created)

The project needs a `develop` branch that is exactly where `main` was when the case starts.
openclaw checks it through the provider API and creates it from `main` if it is missing.

## The issue

This is a **control issue**: its body is only the command. The title keeps the case prefix.

**Title**

```
[E2E-20] Keep develop caught up with main
```

**Body**

```
/catchup --from main --into develop
```

## The process

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | commits a **new** file `docs/upstream-e2e-20.md` on `main`, through the provider API, as an ordinary committer | — | `main` has moved and `develop` has not |
| 2 | creates the control issue above | `autoswe:caught_up` | a PR exists **into `develop`** (not `main`) that brings `docs/upstream-e2e-20.md` with it; the PR body says to merge with a merge commit, not squash; the PR title has no `Fixes #` in it; the issue is still **open** |
| 3 | posts `/catchup` as a comment, with no flags | `autoswe:caught_up` | the **same** PR is updated (same number, no second PR into `develop`), and the completion comment says the run is done |

## Status path

```
pending → catching_up → caught_up → catching_up → caught_up
```

## Must never appear

`failed` · `error` · `synced` · `shipped` (a control issue never ships its own PR; the catch-up PR
is not the issue's work branch)

## Why this case exists

This is the whole point of `/catchup`: keep a downstream branch caught up without touching the
work branch of any issue. Three things are under test. The PR must target the **downstream**
branch, not the repo default. The control issue must **stay open**, because its PR carries no
closing keyword. A bare `/catchup` on the second run must reuse the stored `--from`/`--into` pair
and update the open PR rather than open a new one. The up-to-date branch cannot be reached by
this case: step 1 guarantees `develop` is behind.
