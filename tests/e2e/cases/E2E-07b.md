# E2E-07b — A rebase conflict is not auto-resolved

| | |
|---|---|
| **Group** | sync |
| **Applies to** | one side pass, any backend |
| **Scoped config** | `SYNC_STRATEGY=rebase` — restore afterwards |
| **Run** | **alone**, after the main sweep |

## The issue

**Title**

```
[E2E-07b] Rewrite line 1 of conflict.md (rebase)
```

**Body**

```
Change the first line of `conflict.md` to `shared: rebase task edit`. Nothing else.
```

## The process

Identical setup to [E2E-07](E2E-07.md), under `SYNC_STRATEGY=rebase`.

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | posts `/fix` | `autoswe:fixed` | line 1 changed on the task branch |
| 2 | sets line 1 of `conflict.md` to `shared: main edit` on the base branch | — | conflicting edit staged |
| 3 | posts `/sync` | `autoswe:failed` | the completion comment names a rebase conflict; the task branch is **not** left mid-rebase |

## Status path

```
pending → fixing → fixed → pending → syncing → failed
```

## Must never appear

`synced` · `error`

## Why this case exists

Under merge, a conflict is handed to the agent ([E2E-07](E2E-07.md)). Under rebase it must
**not** be — rebasing rewrites history, so a model resolving a conflict there can silently
destroy commits. Failing loudly is the correct outcome, and this case exists to keep it that
way.

Restore `SYNC_STRATEGY` before running anything else.
