# E2E-17b — An unauthorised author is ignored

| | |
|---|---|
| **Group** | parsing |
| **Applies to** | one pass is enough |
| **Scoped config** | `ALLOWED_AUTHORS=<owner-login>` — restore to empty afterwards |
| **Run** | **alone.** While the allowlist is set, commands from every other account are ignored, which would starve the rest of the sweep. |

Needs a **second account** that can comment on the test project but is not in the allowlist.

## The issue

```

```

**Body**

```
This issue exists to test the author allowlist. Its commands should be ignored.
```

| 2 | restore `ALLOWED_AUTHORS` to empty | — | confirm the setting is back before running anything else |

## Why this case exists

The allowlist is the access control on a system that runs an agent with full permissions on a
dedicated machine. Anyone who can comment on an issue can otherwise steer it, so the check has
to hold — and it has to hold **silently**: replying "you are not allowed" to an untrusted
account turns any public issue into a way to make the bot post.

An optional second half, if you have the accounts for it: with the allowlist still set, have
the **allowed** account post `/fix` on the same issue and confirm it dispatches normally. That
proves the allowlist is filtering rather than simply broken.
