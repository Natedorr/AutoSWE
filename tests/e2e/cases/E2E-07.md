# E2E-07 — `/sync` with a real conflict, resolved by the agent

| | |
|---|---|
| **Group** | sync |
| **Applies to** | every pass |
| **Scoped config** | none |
| **Run** | with the rest |

## The issue

**Title**

```
[E2E-07] Rewrite line 1 of conflict.md
```

**Body**

```
Change the first line of `conflict.md` to `shared: task-branch edit`. Nothing else.
```

## The process

| # | openclaw does | wait for | then check |
|---|---|---|---|
| 1 | posts `/fix` | `autoswe:fixed` | line 1 of `conflict.md` changed on the task branch |
| 2 | sets line 1 of `conflict.md` to `shared: main edit` on the base branch, through the provider API | — | the same line now differs on both sides — a guaranteed conflict |
| 3 | posts `/sync` | `autoswe:synced` | the merge commit is on the task branch and `conflict.md` contains **no conflict markers**; the agent ran (a comment says so) |

## Status path

```
pending → fixing → fixed → pending → syncing → synced
```

## Must never appear

`failed` · `error`

## Why this case exists

The counterpart to [E2E-06](E2E-06.md). When git cannot merge on its own, the sync handler
escalates to the agent to resolve the conflict rather than failing the task. What must never
survive is a file with conflict markers pushed as if it were resolved.
