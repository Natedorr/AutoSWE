# E2E-01 — Happy path: `/plan` → `/fix` → `/pr`

| | |
|---|---|
| **Group** | core |
| **Applies to** | every pass, both providers |
| **Scoped config** | none |
| **Run** | first. If this case is red, stop the pass — nothing downstream is meaningful. |

## The issue

**Title**

```
[E2E-01] Add a squares() helper to toolbox
```

**Body**

```
`src/toolbox.py` should gain a `squares(n)` function returning a list of the squares of
0..n-1. Add one test for it in `tests/test_toolbox.py`. Nothing else.
```

## The process

| # | openclaw posts | wait for | then check |
|---|---|---|---|
| 1 | `/plan` | `autoswe:planned` | a bot comment carries the plan, and the plan describes the change asked for |
| 2 | `/fix` | `autoswe:fixed` | branch `autoswe/issue-<N>` exists with at least one commit; the commit message carries `Fixes #<N>`; the diff adds `squares()` and a test |
| 3 | `/pr` | `autoswe:shipped` | a PR is open, head `autoswe/issue-<N>`, base the repo's configured `base_branch`; a bot comment links it |

## Status path

```
(new) → pending → planning → planned → pending → fixing → fixed → pending → shipping → shipped
```

## Must never appear

`failed` · `error` · `waiting` · `test_failed`

## Why this case exists

It is the baseline: the plan phase produces a plan, the fix phase produces a commit on the
task branch, and the ship phase turns that branch into a PR. Every other case assumes this
path works and varies one thing about it.

The `Fixes #<N>` trailer and the PR base are worth checking even here — they are the two
things most easily broken by a change elsewhere, and every later case inherits them.
