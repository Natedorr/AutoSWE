# E2E-08 — `/review` with an LGTM verdict

| | |

## The issue

**Title**

```
[E2E-08] Add is_even() to toolbox with a test
```

**Body**

```
Add `is_even(n)` to `src/toolbox.py` returning True for even integers, with a docstring and
one test in `tests/test_toolbox.py`.
```

A small, clean, tested change — nothing for a reviewer to object to.

## The process

| # | openclaw posts | wait for | then check |
|---|---|---|---|
| 1 | `/fix` | `autoswe:fixed` | the helper and its test are on the task branch |
| 2 | `/review` | `autoswe:reviewed` | the review comment carries every required section, ending in a verdict that approves |
| 3 | `/pr` | `autoswe:shipped` | `/pr` was permitted from `reviewed`, and the PR is open |

## Status path

```
pending → fixing → fixed → pending → reviewing → reviewed → pending → shipping → shipped
```

## Must never appear

`failed` · `error` · `test_failed`

## Why this case exists

The approving half of the review gate. [E2E-09](E2E-09.md) and [E2E-10](E2E-10.md) prove that
a bad verdict blocks `/pr`; this proves a good one does not — and that `reviewed` is a state
`/pr` accepts.

If the reviewer objects to this change, that is a soft finding about the review prompt, not a
state-machine bug — but check the objection is substantive before dismissing the case.
